# Blackstone Carry: local debug and audit

Date: September 4, 2026. Scope: existing Windows local application, its two
branches, Claude boundary, calculator model, downloads, build and startup.
No deployment, commit or push was performed. Existing artifact-conversion
changes were preserved.

## Outcome

The six-stage disclosure review completed in the browser and exported all six
outputs with primary-source citations. Both calculator arithmetic and its live
Claude explanation work. A second retrieval was intentionally cancelled and
the local server aborted its upstream request. The application now fails with
bounded, actionable errors instead of repeating paid requests silently.

This is a working learning tool, not validated financial-analysis software.

## Why it appeared stuck

The previous retrieval used dynamic-filtering web search without an explicit
search-use budget. A real retrieval took more than 85 seconds, unlike the
earlier one-word connectivity smoke test. Client retries could repeat a slow
paid stage up to three times while the interface showed little useful progress.
Separate historical startup trouble came from saved environment settings not
reaching Vinext's isolated route runtime.

The fix keeps the same Anthropic provider and model. It uses basic primary-domain
search, at most two uses, explicit per-stage deadlines, no automatic retries,
visible elapsed time, cancellation, and manual resume from the first failed
stage. Bounded search improves predictability but may retrieve less evidence.

## Findings and disposition

| Finding | Change / remaining limit |
| --- | --- |
| Slow search and invisible paid retries | Basic search, two-use cap, server 90-second search / 60-second analysis deadlines, browser deadlines five seconds longer. No automatic retry. |
| No way to stop or recover a partial run | Cancel propagates browser to server; completed stages remain available for manual resume and export in the current page. |
| Search preambles, tool errors and partial responses treated as results | Reject search errors inside HTTP 200 and non-`end_turn` output; exclude pre-search commentary from final retrieval text. |
| Source URLs lost during handoff | Require actual SEC/Blackstone search-citation metadata and retain a citation list. This checks metadata/domain, not every quote's fidelity. |
| Invalid judge JSON could show a misleading verdict | Require three finite 0–10 scores, corresponding notes and an overall assessment before marking Judge done. |
| Duplicate requests / malformed local API input | Synchronous UI guard, single in-process upstream slot, JSON validation, streamed 120 KB body limit, fixed server-side model/search settings. |
| Unauthenticated endpoint could be exposed accidentally | Loopback binding, local-host and same-origin checks. These do not replace authentication; do not tunnel or publicly expose the app. |
| Stale calculator explanations after fund changes | Disable selection during generation, cancel on unmount, clear old narrative when selection changes. |
| Branch switching discarded state | Keep both branch components mounted. No persistence across refresh/closure has been added. |
| Calculator formulas omitted zero floors or obscured LP total | Display formulas now match the deterministic model; invalid numeric inputs are rejected; value conservation is tested. |
| Missing original fund-table provenance | Visible unverified-data/model warning and assumptions on every CSV row. The input data has not been replaced or independently verified. |
| Explanation implied a guaranteed hurdle return | Revised prompt and UI distinguish a distribution-priority threshold from a guaranteed payment, and rounded amounts from exact zero. Revised live output included these caveats. |
| Net IRR warning overstated actual hurdle satisfaction | Warning now identifies a possible model inconsistency, not proof of real carry. Arithmetic and inherited fund values remain unchanged. |
| Windows production launcher selected worker runtime | `npm start` explicitly launches the local Node server, loads saved settings and binds to loopback. Added a double-click development launcher. |
| Narrow screen forced six-stage scrolling before the result | Compact horizontally scrollable stage navigation on narrow screens; original visual theme preserved. |

## Remaining gaps, in priority order

1. **Source and model validity.** Recover the original June 2026 table/document,
   reconcile all inputs and their units/gross-net definitions, and use actual
   cash flows plus fund agreements before any real carry estimate. Committed
   minus available is only a proxy; MOIC times that proxy is not verified cash
   available for distribution. Neither the 12-year cap nor net IRR proves terms.
2. **Independent disclosure verification.** The retriever may mix dated sources
   or miss newer/relevant filings. A judge comparing a memo to AI-assembled
   excerpts cannot detect every omission or hallucination in those excerpts.
   A source-locked filing ingestion and externally reviewed evaluation set would
   be needed for stronger assurance; this audit did not add them.
3. **Persistence.** Save before refreshing/closing. Runs do not continue as
   durable background jobs and cannot resume from a previous browser session.
   Switching branches preserves state, not refreshing or closing the app.
4. **Shared/corporate use.** No user authentication, durable rate limits, cost
   dashboard, tenant isolation, audit-log retention or public deployment exists.
   These require a separate access/deployment design, not just sharing localhost.
5. **Dependency/runtime maturity.** The project remains on its existing Vinext
   beta stack. It now builds and runs on this Windows machine; broader browser,
   OS, upgrade and long-duration reliability testing has not been done.

## Running it

Open `http://localhost:3000` while the local server is running. On a later day,
double-click `START TOOL.cmd` in the project folder and keep that window open.
It uses the already-saved `.env.local` and does not require entering the key
again. If port 3000 is occupied, reuse the running tool or stop its existing
server before starting another copy; do not randomly terminate Node processes.

The site/debugging skill checks were used to verify the full browser-to-API
flow and preserve the existing local app/visual design. No hosting or new
framework migration was inferred from this debugging request.
